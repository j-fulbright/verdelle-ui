# Naming

Component names follow shadcn/ui's (`Button`, `Badge`, `Dialog`, `DialogContent`,
`Table`, `TableRow`, ...). Where we add something shadcn does not have, the name
says what it does on the web, and a name that would clash with or mislead against
shadcn's gets renamed. Record each such case here. A component-by-component comparison of props and parts is in
[`docs/api-coverage.md`](../../docs/api-coverage.md) (in the repository; not part of the published crate).

Sizes, radii and spacing follow shadcn's `nova` style, the only style Verdelle supports (the shadcn default;
other styles may come later).

| Ours | Origin | Why this name |
|---|---|---|
| `Indicator` | gpui-component's `Badge` | A count or dot overlaid on another element (a notification marker). shadcn's `Badge` is the pill label, so the name `Badge` stays with that. |
| `Preset`, `ThemeProvider`, `ThemeStyle`, `ThemeContext`, `ThemeStorage`, `CustomTheme` | ours (names follow shadcn's *preset*) | `Preset` is shadcn's preset code with typed fields. `ThemeProvider` owns `data-theme`, `.dark` and the menu attributes, applies a preset and keeps what people choose and make (`ThemeStorage`, default `localStorage`). `ThemeStyle` adds a theme from pasted shadcn CSS. `CustomTheme` is a saved name plus code and/or CSS. See `docs/presets-and-themes.md`. |
| `ThemePicker` | ours | Choose a theme (card grid). shadcn picks themes in its docs site and CLI. Lists the same themes as `ThemeSwitcher` (provider choices, or `themes`; `value` optional, default the provider's). |
| `ThemeSwitcher` | ours | Compact theme chooser: a Select whose trigger and items show a four-dot swatch (background, primary, accent, first chart colour) and the theme name. With a `ThemeProvider` it needs no props and lists built-in, registered (`ThemeStyle`), saved and preview themes; otherwise controlled (`value`, `on_change`, optional `themes`). The recommended control; `ThemePicker` (cards) stays. |
| `ThemeCustomizer` | ours | An "Appearance" panel for an app: theme and mode, preset code box (summary, fallbacks), fine tuning, pasted CSS, saved themes (rename, delete, export, import), preview card. Named by what it does (it customises the theme); shadcn has only its `/create` page for this. Props: a `show_*` bool per section, `compact`, `max_saved`, `load_fonts`, `on_apply`, `on_save`. Needs a `ThemeProvider`. |
| `SyncedStorage` | ours | A `ThemeStorage` that keeps the values in memory, seeded from the app's server, with write-through hooks (`on_set`, `on_remove`, optional `debounce_ms`) and `load` for values that arrive later. Named by what it does: it keeps the provider's values in sync with a server. Also `theme_init_script_seeded`, the no-flash script for such values. |
| `ModeToggle` | ours | Light/dark icon button (a Button). Inside a `ThemeProvider` it flips the provider's mode (which applies and stores it); outside one it flips `.dark` on `<html>` after hydration and persists nothing. An optional `value: RwSignal<bool>` shares the state with the app. shadcn builds this from a dropdown in its docs site. |
| `Toast`, `ToastProvider`, `ToastViewport`, `ToastTitle`, `ToastDescription`, `ToastAction`, `ToastClose` | Radix / Base UI toast | shadcn's base registry ships Sonner (`sonner.tsx`, a `<Toaster/>` plus an imperative `toast()`), a third-party library with no headless parts, and a newer Base UI `toast.tsx` (`ToastProvider`, `ToastViewport`, `ToastPortal`, `ToastContent`, `ToastIcon`, `ToastList` over a toast manager) that Verdelle does not mirror. We keep the primitive's Radix-shaped parts so a toast can hold custom content, and style them to look like Sonner (popover colours, border, 2xl radius, shadow, 356px wide, six positions, variant icons, swipe to dismiss). Not provided from Sonner: stacked/expanded card stack, `loading` type, `toast.promise`. |
| `Toaster`, `use_toaster()` | Sonner's `<Toaster/>` and `toast()` | The batteries-included path: `Toaster` renders provider, viewport and the list; `use_toaster().show(ToastData::new(..))` shows one. Sonner's `error` type is `ToastVariant::Destructive`, as Alert and Button name it. |
| `Size` | ours | The one size enum (`XSmall`, `Small`, `Medium` = shadcn's default, `Large`), carried as `data-size`. |
| `Side`, `Align` | Radix/Base UI `side`, `align` | Typed versions of the string props (`"top"`, `"start"`) of Popover, Dropdown Menu and Tooltip content. |
| `MenuItemVariant` | shadcn `variant` on `DropdownMenuItem` | `Default` and `Destructive`, as shadcn's `data-variant`. |
| `PopoverClose` | Base UI `Popover.Close` | A button that closes the popover; shadcn's file does not export it. |
| `DropdownMenuShortcut` | shadcn | A key-hint label only; it does not bind keys. |
| Trigger `variant` | shadcn `render={<Button/>}` | `PopoverTrigger`, `DropdownMenuTrigger`, `TooltipTrigger` take `variant`/`size`/`icon_only` to look like a `Button`; without `variant` they are bare buttons styled by `class`. |
| `Input`, `Textarea` | shadcn | A frame around a native `<input>`/`<textarea>` (prefix, suffix and clear button are extras). |
| `AlertDialog` (no `AlertDialogTrigger`, `Content`, `Overlay`, `Portal`) | shadcn | One component: the native `<dialog>` is the content, overlay and portal (its `::backdrop` and top layer). Open it by setting `open`; `AlertDialogAction`/`AlertDialogCancel` are Buttons that close it. |
| `Progress` (no `ProgressTrack`/`ProgressIndicator`) | shadcn / Base UI | The track and fill are drawn by `Progress` itself; `ProgressLabel` and `ProgressValue` go in its children. |
| `CollapsibleTrigger` `variant` | shadcn `render={<Button/>}` | We cannot swap the element, so the trigger takes a Button's look when `variant` is set. |
| `ScrollArea` `orientation` (no `ScrollBar`) | shadcn | shadcn adds a `ScrollBar` child for horizontal; here it is one prop, `ScrollAreaOrientation::{Vertical, Horizontal, Both}`. |
| `Empty` `bordered` | shadcn's `Empty` | shadcn's examples add `border border-dashed` through `className`; the component only sets the dash style. We expose it as a `bordered` prop (a `data-bordered` attribute). |
| `Item` `href` | Base UI `render` prop | shadcn's `Item` renders as `<a>` through `render`. We take `href` and render an anchor (hover fill and focus ring), else a `<div>`. `size` is our shared `Size` (`Medium` = shadcn's `default`, `Large` falls back to it). |
| `BreadcrumbLink` | shadcn | Takes `href` and renders a plain `<a>`; there is no `render` prop, so wrap a router link with the same class if needed. |
| `PaginationLink` `active` / `icon_only` | shadcn's `isActive` / `size="icon"` | Snake-case boolean `active`; `size` is the shared `Size` and `icon_only` (default true) makes it square, as on Button. Also takes `on_click`. |
| `ButtonGroup` `orientation` | shadcn | Reuses the Separator's `Orientation` enum. `ButtonGroupSeparator` defaults to `Vertical`, as shadcn's. |
| `InputGroupInput`, `InputGroupTextarea` | shadcn | Bare native controls (no frame), because the group draws the frame; shadcn wraps its `Input`/`Textarea` and strips their border. `InputGroupButton` wraps our `Button`; its `InputGroupButtonSize` is shadcn's `xs`/`sm`/`icon-xs`/`icon-sm`. `disabled` and `invalid` are set once on `InputGroup`. |
| `NativeSelect` | shadcn | `size` is the shared `Size` (`Small` = shadcn's `sm`, anything else = `default`); `value` is an optional two-way signal. |
| `AspectRatio` | shadcn | `ratio` is a `f64` (width / height). |
| `ToggleGroup` `multiple` | Base UI's toggle group | Radix has `type="single"\|"multiple"`; Base UI (and shadcn's base registry) use a boolean `multiple`. Values are always a list. |
| `Slider` | shadcn | shadcn's Slider takes a value array and renders one thumb per entry; ours does the same (`thumb_labels` names the thumbs). `on_value_commit` fires when a drag ends or a key is pressed (shadcn's `onValueCommitted`). Parts (Control, Track, Range, Thumb) are internal, not exported. There is no `name` and no hidden form input. |
| `InputOtp`, `InputOtpGroup`, `InputOtpSlot`, `InputOtpSeparator` | shadcn (input-otp) | Same parts. `pattern` takes `InputValidationType` (digits, alphanumeric, any) instead of a regex. Each slot is its own `<input>` (the primitive is Radix's OneTimePasswordField), where shadcn's uses one hidden input and draws the slots. |
| `Field`, `FieldGroup`, `FieldSet`, `FieldLegend`, `FieldLabel`, `FieldContent`, `FieldTitle`, `FieldDescription`, `FieldSeparator`, `FieldError` | shadcn | Same parts. `FieldError` takes `errors: Vec<String>` (shadcn takes objects with a `message`). Field does not wire ids for you. |
| `HoverCard`, `HoverCardTrigger`, `HoverCardContent` | shadcn / Base UI `PreviewCard` | shadcn names them HoverCard over Base UI's Preview Card; same three parts. `HoverCardTrigger` is an `<a>` and takes `href`; delays are `open_delay` (600) and `close_delay` (300), Base UI's defaults. |
| `NavigationMenu`, `NavigationMenuList`, `NavigationMenuItem`, `NavigationMenuTrigger`, `NavigationMenuContent`, `NavigationMenuLink`, `NavigationMenuIndicator` | shadcn | Same parts. shadcn's `NavigationMenuPositioner` (portal, positioner, popup and viewport) is built into `NavigationMenu`, switched by `viewport` (default true; shadcn's older Radix version had the same flag). `navigationMenuTriggerStyle()` is `NavigationMenuLink trigger_style=true`. `orientation` is the shared `Orientation`. The value is a string and `on_value_change` gets `""` on close (as Radix). Extras: `label`, `delay_duration`, `skip_delay_duration`; `vdl-nav__link-title` and `vdl-nav__link-description` classes for title-and-summary links. Content motion is Radix's `data-motion`, not Base UI's `data-activation-direction`. |
| `Combobox`, `ComboboxInput`, `ComboboxContent`, `ComboboxList`, `ComboboxItem`, `ComboboxGroup`, `ComboboxLabel`, `ComboboxEmpty`, `ComboboxSeparator`, `ComboboxChips`, `ComboboxChip`, `ComboboxChipsInput` | shadcn (Base UI Combobox) | Same parts. `multiple` is a boolean prop with its own `values` / `on_values_change` (shadcn passes arrays to the same `value`); `on_value_change` gets `None` when cleared. `ComboboxInput` takes `show_trigger` and `show_clear` as shadcn's. The popup anchors to the input frame (or `ComboboxChips`); shadcn's `anchor` prop and `useComboboxAnchor()` are not needed. Items take `label` (matched and shown in the input) and `keywords`; `items` on the root gives (value, label) pairs for the closed input. No `ComboboxCollection` / `ComboboxValue` / `ComboboxTrigger` / `ComboboxClear` exports: the first two serve Base UI's data-driven items and popup-trigger form, the last two are built into `ComboboxInput`. |
| `ComboboxChipList` | ours | A `ComboboxChip` for every picked value, with its label; shadcn's examples map over the value array by hand. `use_combobox_values()` gives (value, label) pairs for custom chips. |
| `Command`, `CommandInput`, `CommandList`, `CommandGroup`, `CommandItem`, `CommandShortcut`, `CommandSeparator`, `CommandEmpty`, `CommandDialog` | shadcn (cmdk) | Same parts. `CommandGroup` takes `heading` as text. `CommandItem` `value` is required (cmdk derives it from the text) and `label`/`keywords` are what a search matches; `on_select` gets the value. `on_value_change` reports the highlighted value but there is no controlled `value`. No sorting by score, `CommandLoading` or vim bindings. `CommandDialog` takes `open: RwSignal<bool>` as `Dialog` does. |
| `FilterQuery`, `contains_filter`, `starts_with_filter`, `fuzzy_filter` | Base UI `filter` | The matcher a Combobox or Command takes: a closure over the item's value, label, keywords and the typed text. Defaults to every typed word contained in the label or keywords. |

| `DataTable`, `DataTableColumn`, `DataTableState`, `DataTableColumnFilter` | shadcn's Data Table guide | shadcn's guide is a recipe on TanStack Table (React-only), not a component, so this is our own API with the guide's features: `DataTableColumn` is a typed builder (`new`, `text`, `sort_by`, `sort_by_key`, `filter_text`, `align`, `width`, `hideable`, `hidden_by_default`, `header_hidden`, `footer`); `DataTableState` is the table's signals (sort, search, column filters, page, selection, hidden columns) so the app can read or drive them; `total_rows` switches to server-side mode; `DataTableColumnFilter` is a select bound to one column's filter. The headless model (sort cycle, filter, sort, page window, selection state) is `verdelle_ui::primitives::data_table`, plain functions with tests. Cell checkboxes are native inputs with the `vdl-checkbox` class, not the `Checkbox` component (row state is a set of keys, not a signal per row). `Checkbox` gained `indeterminate`. |
| `Sheet`, `SheetClose` (no `SheetTrigger`, `SheetContent`, `SheetPortal`, `SheetOverlay`) | shadcn | One component, like `Dialog`: the native `<dialog>` is the content, overlay and portal. Open it by setting `open`. `side` is our shared `Side` (default `Right`, shadcn's). Like `Dialog` it plays an exit animation (the element is closed after it). Extras: `overlay_closable`, `close_on_escape`, `show_close_button`, as on `Dialog`. `SheetClose` is a `Button` that closes the enclosing sheet. |
| `Drawer`, `DrawerTrigger`, `DrawerClose`, `DrawerHeader`, `DrawerFooter`, `DrawerTitle`, `DrawerDescription` (no `DrawerContent`, `DrawerPortal`, `DrawerOverlay`, `DrawerHandle`) | shadcn (vaul; Base UI drawer in the newer registry) | One component, like `Sheet`: the native `<dialog>` is content, overlay and portal; open it with `open`. `DrawerTrigger` takes the same `open` signal (it cannot sit inside the drawer). `direction` is `DrawerDirection::{Bottom, Top, Left, Right}` (vaul's `direction`; Base UI's `swipeDirection` names the swipe, which is the opposite word). `snap_points` are visible fractions (vaul), `default_snap` and `active_snap` are indices into the sorted list (vaul uses the values; a float is a bad key). `show_handle` (Base UI's `showSwipeHandle`, on by default here), `dismissible` (vaul; covers swipe, Escape and backdrop), `modal` (vaul/Base UI), `scale_background` (vaul's `shouldScaleBackground`). |
| `DrawerWrapper` | vaul (`vaul-drawer-wrapper` attribute) | The element that recedes behind a drawer with `scale_background`; shadcn has no such component. |
| `Sidebar` and its parts (`SidebarProvider`, `SidebarTrigger`, `SidebarRail`, `SidebarInset`, `SidebarInput`, `SidebarHeader`, `SidebarFooter`, `SidebarSeparator`, `SidebarContent`, `SidebarGroup`, `SidebarGroupLabel`, `SidebarGroupAction`, `SidebarGroupContent`, `SidebarMenu`, `SidebarMenuItem`, `SidebarMenuButton`, `SidebarMenuAction`, `SidebarMenuBadge`, `SidebarMenuSkeleton`, `SidebarMenuSub`, `SidebarMenuSubItem`, `SidebarMenuSubButton`, `use_sidebar()`) | shadcn | Same parts. `side`, `variant`, `collapsible` are the enums `SidebarSide`, `SidebarVariant`, `SidebarCollapsible`. No `render` prop: `SidebarMenuButton` and `SidebarMenuSubButton` render an `<a>` when given `href`, else a `<button>`; `SidebarGroupLabel` is always a `<div>`. `SidebarMenuButton` `tooltip` is text and shows only while collapsed to icons. `isActive` is `is_active`. `SidebarMenuSkeleton` takes a fixed `width` (shadcn randomises, which would differ between server and browser). Extras: `SidebarProvider` `contained` (position inside the provider instead of the window), `persist` (cookie `sidebar_state`, as shadcn), `keyboard_shortcut`, `style`; `Sidebar` `label` (the mobile sheet's accessible name); `SidebarInput` is hidden while collapsed to icons. Below 768px the sidebar is drawn as a `Sheet` (shadcn: `useIsMobile`); `SidebarContext` has `open`, `open_mobile`, `is_mobile` signals instead of shadcn's `state`/`isMobile` values. |
| `AppNav`, `NavItem`, `NavMatch`, `AppShell`, `ShellLayout`, `ShellContent`, `SidebarShell`, `TopBarShell`, `ShellUser` | none (Verdelle's own) | Not in shadcn or Base UI: a page frame driven by one plain-data menu. `AppNav` is a list of `NavItem`s (a link, or a group with `children`; `icon`, `badge`, `disabled`, `visible: Signal<bool>` for permissions, `NavMatch::{Exact, Prefix}`); it has no layout, so `AppShell` can draw it as a `SidebarShell` (on `Sidebar`, `Sheet` and `Collapsible`) or a `TopBarShell` (on `DropdownMenu`) by changing `layout`. A child `NavItem` takes an `icon` like a top-level one: drawn in sidebar sub-menu rows and top-bar dropdown and phone-menu rows. |
| `ContextMenu*`, `Menubar*` item parts | shadcn | Same names as shadcn. | `Icon`, `IconName` | Lucide (via shadcn's icon library choice) | One component and one enum instead of a component per icon: `<Icon name=IconName::Check />`. | `Toolbar`, `ToolbarButton`, `ToolbarToggleGroup`, `ToolbarToggleItem`, `ToolbarLink`, `ToolbarInput`, `ToolbarSeparator` | Base UI Toolbar | shadcn has no Toolbar. ## Table layout extras (responsive, row state, detail rows)
